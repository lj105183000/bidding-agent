## 2. 环境准备与配置

### 2.1 环境要求与安装

```bash
# Python ≥3.12 (uv 管理), Node.js ≥18
uv sync                          # 后端依赖 (含 dev 组 pytest)
cd frontend && npm install       # 前端依赖
```

依赖锁定在 `uv.lock` / `package-lock.json`；首次 `uv sync` 会按 pyproject 中的镜像源拉取。

### 2.2 首次运行的模型下载

BGE 嵌入模型与 CrossEncoder 精排模型在**首次实际使用时**从 Hugging Face 下载（懒加载）。国内网络请在 `.env` 设置镜像：

```bash
HF_ENDPOINT=https://hf-mirror.com
```

### 2.4 配置语义要点

- `load_dotenv(override=False)`：`.env` 只填充未设置的变量，**容器/CI 注入的真实环境变量优先**。
- 出站请求一律 `trust_env=False`，不继承操作系统代理；需要代理时显式配置 `HTTP_PROXY`/`HTTPS_PROXY`。
- 测试无需 `.env`：根 `conftest.py` 预置 QDRANT_URL/QDRANT_API_KEY/DEEPSEEK_API_KEY 占位值。

## 3. 日常开发流程

### 3.1 启动后端

```bash
python main.py api     # http://localhost:8001 (带 reload=True 热重载, 开发用)
python main.py dev     # 后台线程起后端 + 打印前端启动提示
```

- 交互式 API 文档：`http://localhost:8001/docs`
- 启动耗时取决于模型预热（首次会下载 BGE/CrossEncoder，见后端日志「嵌入/精排模型预热完成」）

### 3.2 启动前端

```bash
cd frontend && npm run dev     # http://localhost:3000
```

两条请求路径（重要）：

- **普通 API**：走 Next.js `rewrites` 代理（`/api/*` → `http://localhost:8001/api/*`）
- **SSE 流式**：`lib/api.ts` 中**绕过代理直连** `http://localhost:8001`（Next 代理会缓冲整个 SSE 响应导致流式失效）；生产环境用 `NEXT_PUBLIC_API_BASE` 显式指定后端地址

### 3.3 健康检查

`GET /api/health` 返回各组件就绪状态与延迟（30s 缓存）：

| 字段                                                       | 含义                           |
| -------------------------------------------------------- | ---------------------------- |
| `ready`                                                  | RAG 流水线已初始化（vocab.json 加载成功） |
| `agent_ready`                                            | Agent 初始化完成                  |
| `graph_ready` / `pg_ready`                               | Neo4j / PostgreSQL 已连接       |
| `points_count`                                           | Qdrant 集合向量点数                |
| `latencies.neo4j_ms` / `postgres_ms` / `qdrant_check_ms` | 探测延迟；`-1` 表示该组件异常            |

### 3.4 日志

- 配置入口：`src/logging_config.py`（格式 `时间 [级别] 模块名: 消息`，stdout 输出）
- `src` 包日志级别 INFO；第三方库（httpx/openai/urllib3/sentence_transformers/jieba）压制到 WARNING
- 约定：**技术细节（服务地址、原始异常、完整 SQL/查询）只进日志，用户可见的错误提示不泄露内部信息**

## 4. 数据准备与导入

### 4.1 知识库（Qdrant）

**数据格式**：`data/` 目录下任意 Excel（递归查找第一个 `.xlsx/.xls`），两列 `问/答`（或 `question/answer`，或前两列），清洗规则：去空行、去重复问题。

```bash
python main.py ingest        # 全量重建: fit 词汇表 → 删旧集合 → 双编码 → 写入 → 保存 vocab.json
```

- `ingest_data(force=True)` 总是重建集合，已存在数据会被覆盖
- 词汇表落盘为 `data/vocab.json`，**查询端必须存在且与向量数据一致**；更换数据后必须重新 ingest，否则 sparse 检索维度/词表错位
- 编码失败的行跳过并记日志，不中断整体导入

### 4.2 数据管道（batch/）

五个脚本全部 CWD 无关（内部解析项目根路径）、支持 `--dry-run`、GBK CSV、PermissionError 提示（Excel 被占用时）、空数据提前返回。**按顺序执行**：

| 序号  | 脚本                             | 输入 → 输出                                                                                           | 用途                                                                                                                                                                                                                                                      |
| --- | ------------------------------ | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `python batch/去重.py`           | `data/raw/招标采购标的物信息提取训练数据.xlsx` → `data/processed/<原名>_2.xlsx`                                    | 按「项目编号+中标金额」联合去重，保留**空值最少**的一条，并列时取**发布时间最新**的一条。缺「项目编号」的行无法判重，**全部保留**（按金额硬合并会把不同项目错误地压成一条）。实测 8789 → 8751 行                                                                                                                                           |
| 2   | `python batch/提数据_编JSONL.py`   | `data/processed/<原名>_2.xlsx` → `data/batch/batch_requests.jsonl`                                  | 提取「项目名称」生成 batch 请求文件（智谱 `/v4/chat/completions`，每行一个请求对象）。**`custom_id = request-<数据行号>`**（第 1 条数据 = `request-1`，即 Excel 第 2 行）：空名称的行不发请求，但序号照旧占位，第 4 步靠它反查行号。实测 8751 行 → 8751 条、约 10MB（上限 50000 条 / 100MB，超限本地拦下）。`--src`/`-o`/`--model`/`--limit` 可覆盖 |
| 3   | `python batch/按custom_id排序.py` | `data/batch/batch_results_raw.jsonl` → 同目录 `batch_results_processed.jsonl`                        | batch 接口按完成先后返回结果，顺序不保证，这一步把结果排回行号顺序供第 4 步回填。**必须按序号数值排**（`int(custom_id.split("-")[-1])`），字符串排序会把 10 号之后整体插到 2 号前面。对其他 JSONL 用 `--src` 即可，输出落在源文件旁加 `_sorted`（对第 2 步的请求文件跑是幂等的，可用来验证）。坏行（非法 JSON / 缺 custom_id / 序号不可解析）一律报错并指出行号，不跳过                  |
| 4   | `python batch/提数据_插标的物.py`     | `data/batch/batch_results_processed.jsonl` + `data/processed/<原名>_2.xlsx` → 同目录 `<原名>_2_标的物.xlsx` | 读**结果**文件（不是请求文件——拿错会明确报错），按 `custom_id` 序号填进第 N 行（`.iloc[N-1]`）。缺号留空（第 2 步跳过空名称所致），**序号越界直接拦下**（说明结果与这张表不是一对）。「标的物」列已存在则原地填，否则追加到最后一列。解析时剥掉模型偶尔附带的 markdown 围栏 / `标的物：` 标签 / 引号 / 句末标点                                                                 |
| 5   | `python batch/统计数据_插交易频次.py`   | `…_标的物.xlsx` → `data/processed/标的物_交易频次.xlsx`                                                     | 标的物频次统计（两列：标的物、交易频次）。第 1 步已去重，故**每行 = 一笔中标交易**，出现次数即交易频次。**未抽出标的物的行不计入**（否则空值会污染榜首）；**只按字面统计、不做同义归并**（`空调` 与 `空调设备` 算两个——归并属语义问题，归第 2 步的提示词管）。频次降序，并列按标的物码点升序，保证同一输入两次跑出同一文件。输入在 `data/` 下自动探测（认不下确切名字就取最新的 `*_标的物.xlsx`）                               |

> 全管道可用 `--dry-run` 预演；正式执行前建议关闭对应 Excel 文件（PermissionError 会给出明确提示）。
> 
> **custom_id 排序陷阱**：`request-10` 的字典序排在 `request-2` 前面，所以第 3 步必须按序号**数值**排序（`int(custom_id.split("-")[-1])`），不能直接排字符串——否则回填的标的物会整体错位。

**第 2 步与第 3 步之间的提交环节**（不属于上面 5 个数据处理步骤，是原本靠控制台手点的运维动作）：

```bash
python batch/提交batch任务.py            # 上传 → 建任务 → 等完成 → 下载到 data/batch/
python batch/提交batch任务.py --status   # 只看进度
python batch/提交batch任务.py --new      # 忽略已有任务重新提交（会重复计费）
```

- 结果按项目约定命名：`data/batch/batch_results_raw.jsonl`（第 3 步的输入名）；平台的失败请求走 `error_file_id` 单独返回，落 `batch_results_errors.jsonl`
- `batch_id` 记在 `data/batch/batch_job.json`，中断后用同一条命令接着等；**默认续用已有任务**，重新提交必须显式 `--new`（8751 条 = 8751 次真实计费）
- **前置条件：开放平台完成实名认证**，否则建任务返回 `401 / code 1000「调用Batch API服务，请先在开放平台完成实名认证」`（上传正常，只是建不了任务）
- ⚠ **模型名必须落在批量接口的支持列表内**：`.env` 的 `ZHIPU_MODEL=glm-4.7-flashx` 是 **Chat 侧**模型名，批量接口不认——上传时会以 `1210 模型名称错误` 整批拒掉并回显支持列表。批量侧用 `glm-4-flashx-250414`（`提数据_编JSONL.py` 的 `BATCH_MODEL` 默认值，`--model` 可覆盖）

### 4.3 知识图谱（Neo4j）

```bash
python src/database/to_neo4j.py --password <pwd> --clear
```

- 星型 schema：SubjectMatter 中心节点 + Purchaser/Supplier/Agency/Location + HAS_TRANSACTION 交易关系
- `--clear` 先清空库再导入；不带则追加

### 4.4 结构化数据库（PostgreSQL）

```bash
python src/database/to_postgresql.py
```

- 导入目标表 `bidding_procurement`（字段白名单见 `src/database/postgresql_client.py` 的 `ALLOWED_FIELDS`）
- `conversations`（会话 JSONB）与 `feedback`（用户反馈）两张表由客户端**连接时自动创建**，无需手动建表

## 5. API 接口契约

所有端点前缀 `/api`。错误码约定：`400` 参数问题、`413` 图片过大、`422` 枚举校验失败、`429` 限流、`500` 处理异常、`503` 依赖未就绪。

> **实现状态**：已落地 `/api/chat/stream`、`/api/chat`、`/api/ask`、`/api/health` 四个端点。
> `/api/vision`、`/api/conversations*`、`/api/feedback` 尚未实现（属视觉链路与 PostgreSQL 范围）。
> `ChatRequest` 当前只接受 `question` 与 `history`；`web_search_enabled` / `provider` / `deep_thinking_enabled` 待联网类工具与多 provider 落地后补上。
> `/api/chat` 承担**评测与脚本调用**的角色（`eval/` 的 Agent 评测待落地），不再标记为废弃。
> 
> **`/api/chat*` 走 `BiddingAgent`**（ReAct 工具循环，见 §8.1）；`/api/ask` 不经过 Agent、不调用大模型，直接返回最匹配的问答原文。

### 5.1 对话类

**POST /api/chat/stream**（推荐，SSE 流式）

请求 `ChatRequest`：

| 字段                      | 类型         | 默认    | 说明                               |
| ----------------------- | ---------- | ----- | -------------------------------- |
| `question`              | str        | —     | 必填，空串 400                        |
| `history`               | list[dict] | null  | `[{role, content}]`，后端只保留最近 5 轮  |
| `web_search_enabled`    | bool       | false | 开启后动态挂载 search_web/search_exa 工具 |
| `provider`              | str        | ""    | 空 = 取配置 `LLM_PROVIDER`；可逐请求切换    |
| `deep_thinking_enabled` | bool       | false | 深度思考（切换思考模型或提示词注入，见组件工作机制 §11）   |

响应：`text/event-stream`（事件协议见 §6）。`503` Agent 未就绪。

**POST /api/chat**（非流式，已废弃，保留兼容）：同请求体，返回 `{answer, sources, tool_called, tool_name}`。

**POST /api/ask**（直接 RAG，不走 Agent 工具）：`{question, top_k=5}` → `{answer, sources:[{question,answer,score}]}`。

### 5.2 视觉类

**POST /api/vision**：`{image_base64, prompt="请详细描述这张图片的内容"}` → `{analysis, model}`。

- base64 字符数超过 `4_000_000`（约 3MB）→ `413`（前端已做 canvas 压缩兜底，此限制防绕过前端直传）
- 视觉服务未就绪（无 ZHIPU_API_KEY）→ `503`

### 5.3 会话与反馈（PostgreSQL）

| 方法/路径                                    | 请求                                       | 响应                       | 说明                                              |
| ---------------------------------------- | ---------------------------------------- | ------------------------ | ----------------------------------------------- |
| POST `/api/conversations`                | `{session_id, title="", messages: []}`   | `{status:"ok"}`          | 新会话插入，已存在则更新；空 title 保留库中原值；数据库故障 503           |
| GET `/api/conversations`                 | `?q=关键词`                                 | 会话列表                     | `q` 非空时全文搜索（messages::text + title，LIKE 通配符已转义） |
| GET `/api/conversations/{session_id}`    | —                                        | `{session_id, messages}` | 不存在时 messages 为 []                              |
| DELETE `/api/conversations`              | —                                        | `{status:"ok"}`          | 清空全部                                            |
| DELETE `/api/conversations/{session_id}` | —                                        | `{status:"ok"}`          | 删除单个                                            |
| POST `/api/feedback`                     | `{session_id, question, answer, rating}` | `{status:"ok"}`          | `rating` 枚举 `"up"/"down"`，非法值 422               |

> 会话保存失败时后端返回 503（不再静默成功），前端据此提示「会话保存失败」。

### 5.4 限流

`/api/chat*` 前缀的端点按客户端 IP 滑动窗口限流：**30 次 / 60 秒**，超限 `429`。限流状态在进程内（单进程部署约束见 §11.1）。

## 6. SSE 流式事件协议

### 6.1 帧格式

每帧一行 JSON（`ensure_ascii=False` 保留中文），以 `data: ` 前缀，帧间空行分隔。**首帧是 2KB padding 注释**（`:` + 空格），用于强制代理/缓冲区立即 flush。

### 6.2 事件类型

| type       | 触发时机        | 字段        | 前端处理                        |
| ---------- | ----------- | --------- | --------------------------- |
| `status`   | 阶段变化        | `content` | 覆盖「思考中」占位消息文字               |
| `token`    | 正文增量        | `content` | 累积渲染（40 字符小帧 + 20ms 延时后端切分） |
| `thinking` | 思考增量（仅深度思考） | `content` | 累积到紫色折叠块（默认展开，**不落库**）      |
| `reset`    | 检出工具调用文本泄漏  | —         | **清空已流正文**，等后续 token 帧重来    |
| `done`     | 正常结束        | 见下        | 组装最终消息、替换占位、持久化             |
| `error`    | 异常结束        | `content` | 展示错误信息                      |

### 6.3 status 帧序列（ReAct 多轮）

```
正在初始化... → [正在深度思考...] → 正在检索与搜索...
→ 正在分析检索结果... → 正在补充检索（第N轮）...（≤4 轮，可循环）
→ 正在生成回答... → done
```

RAG 降级路径：`正在检索知识库... → 正在生成回答... → done`。

> **实现状态**：ReAct 路径与 RAG 降级路径均已落地（`src/agent/core.py` 的 `chat_events`）；
> `正在深度思考...` 属深度思考功能，尚未实现。
> 
> **工具文本泄漏与 `reset`**：模型偶尔把工具调用当正文吐出来（实测 DeepSeek 有两种方言：
> JSON 式 `<tool_call>{...}` 与 XML 式 `<tool calls><invoke name=…>`）。后端在流式开头缓冲
> `STREAM_FLUSH_CHARS` 个字符做检测，命中就发 `reset` 清屏、**真正执行**该调用，再重新生成；
> 前端必须正确处理 `reset`（清空已渲染正文重来），否则用户会先看到一段调用语法。
> 根因治理在 `prompts.FINAL_STAGE_INSTRUCTION`——最终生成不带 `tools` 参数，必须明说"本阶段无工具可用"。

### 6.4 done 帧字段

```json
{"type":"done","sources":[...],"web_sources":[...],"tool_called":true,
 "tool_name":"search_knowledge_graph","elapsed_ms":12345,
 "phase_times":[["首轮分析",1200],["检索与搜索",2300],["生成回答",3100]]}
```

| 字段            | 说明                                                                     |
| ------------- | ---------------------------------------------------------------------- |
| `sources`     | 知识库来源 `[{question, answer, score}]`（多轮跨轮累积去重）                          |
| `web_sources` | 联网来源 `[{question, answer, score, url}]`（CrossEncoder 重排，score 归一化 0-1） |
| `tool_name`   | **单字符串** = 最后一个执行完成的工具名，未调用工具时为空串（前端徽标与 eval 依赖此语义，勿改数组）               |
| `tool_called` | 是否**执行过**工具（与检索到几条无关：0 条命中仍算执行过）。降级路径直接检索时同样为 `true`                   |
| `elapsed_ms`  | 收到请求到 done 的总耗时                                                        |
| `phase_times` | 分阶段耗时；无工具直答仅「首轮分析」一项；RAG 降级为「检索/生成」两项                                  |

### 6.5 前端解析约定（lib/api.ts + page.tsx）

- 逐行解析，仅处理 `data: ` 前缀行；单行 JSON 失败不中断整个流（如 `[DONE]` 标记）
- 流结束但未收到 `done`/`error` → 视为后端异常截断，兜底提示「连接中断，请重试」
- 异常时若已有流式正文则保留内容并附加「⚠️ 回答可能不完整」提示，无内容则错误横幅

## 8. 后端开发指南

### 8.1 架构约定

- **单例模式**：`settings / embedder / reranker / vector_store / rag_pipeline / bidding_agent / neo4j_client / postgresql_client / web_search_client / exa_search_client / rate_limiter` 均为模块级单例；模型对象**懒加载 + 双重检查锁**（并发首用只加载一份）
- **事件流架构**：`_chat_events` 产出结构化事件元组，`chat_stream` 序列化为 SSE、`chat` 收集为 dict——两条路径共用同一流程，新增逻辑只改一处
- **工具结果契约**：数据库/图谱/联网工具统一返回 `{"success", "data"/"results", "error"}`，格式化器处理所有失败分支，Agent 永不因后端宕机崩溃
- **异常分级**：完整异常（地址/原始错误）只进日志；用户可见提示按「本地模型/远程服务」区分措辞

### 8.2 关键常量（src/agent/constants.py）

| 常量                                          | 值         | 含义                                |
| ------------------------------------------- | --------- | --------------------------------- |
| `MAX_HISTORY_ROUNDS`                        | 5         | 对话历史保留轮数（截断）                      |
| `MAX_TOOL_ROUNDS`                           | 4         | ReAct 工具轮次上限（不含最终生成回合）            |
| `MAX_TOKENS_DEEP`                           | 8192      | 深度思考输出预算（reasoning 计入 max_tokens） |
| `STREAM_FLUSH_CHARS`                        | 80        | 流式防泄漏缓冲阈值                         |
| `STREAM_CHUNK_CHARS` / `STREAM_CHUNK_DELAY` | 40 / 0.02 | 小帧切分与帧间延时                         |

### 8.3 如何新增一个工具

1. `src/tools/rag_tools.py`：定义执行函数（返回 `(格式化文本, sources 列表)`）+ `BaseTool` 子类（name/description/parameters，含参数枚举白名单）+ 注册进 `TOOL_EXECUTORS`
2. 如需质量标签：在 `src/agent/react_loop.py` 的 `_validate_result` 增加分支
3. `src/agent/prompts.py` 的 SYSTEM_PROMPT 补充该工具的选择映射
4. 前端 `ChatMessage.tsx` 增加对应工具徽标分支（未知名兜底显示「已搜索知识库」）
5. 联网类工具需在 `_build_context` 的 `web_search_enabled` 分支挂载，并在 `_chat_stream_tools` 的 web_sources 分支收集来源

### 8.4 如何新增一个技能

`src/skills/<name>/SKILL.md`：frontmatter 声明 `name` 与 `description`（**alias = description 中破折号/冒号前半段**，作为中文触发短语），正文为执行指南。匹配逻辑见 `src/agent/skills.py` 的 `_match_skills`（点名/别名/指代三层）。技能是上下文注入，无额外工具往返。

### 8.5 如何新增一个 LLM Provider

`src/clients/`：实现 `BaseLLMClient`（`chat / chat_stream / chat_stream_thinking / chat_raw / model_name / provider`），在 `llm_factory.get_llm_client` 注册；深度思考模型切换在 `core.py` 的 `_thinking_model` 补充。注意 `chat_stream_thinking` 需把 reasoning 与正文分离产出（kind ∈ thinking/content），否则深度思考模式退化。

### 8.6 数据库客户端约定（src/database/）

- 查询模板经 `query(query_type, **kwargs)` 路由，参数化查询 + 字段/聚合函数白名单校验（防注入）
- PostgreSQL 用 `PostgreSQLQueryError` 区分「无结果」（返回 []）与「故障」（抛异常）
- Neo4j 查询用 `begin_transaction(timeout=30)` 防慢查询挂起工具线程

## 11. 部署指南

### 11.1 后端部署

```bash
uv sync
```

- 首次启动会下载嵌入/精排模型（提前预热或保证可访问模型源，见 §2.2）
- `main.py api` 带 `reload=True` 仅用于开发

```bash
cd frontend
NEXT_PUBLIC_API_BASE=https://你的后端地址 npm run build   # 构建时注入 SSE 直连地址
npm run start
```

`NEXT_PUBLIC_API_BASE` 未设置时生产环境回退同源相对路径——若前端与后端不同源或经反向代理，**必须显式设置**（SSE 不能走会缓冲的反向代理配置，需对 `/api/chat/stream` 关闭代理缓冲：`proxy_buffering off`，响应头已带 `X-Accel-Buffering: no`）。

### 11.4 CORS

`CORS_ORIGINS`：逗号分隔白名单（如 `https://qa.example.com,https://admin.example.com`），`*` 允许所有，未设置时仅本地开发端口。

| 首次问答极慢 / 工具 30s 超时                    | 嵌入/精排模型冷启动下载                                         | 等预热完成日志；离线可提前跑一次 ingest 触发下载                 |
| 健康检查 Qdrant `-1` / 检索空结果              | Qdrant 连接失败或集合不存在                                    | 检查 QDRANT_*；确认已 `python main.py ingest`      |
| 检索结果质量骤降                              | vocab.json 与向量数据不一致                                  | 更换数据后重新 ingest（词表必须与集合同步重建）                  |
| 「知识库未就绪」503                           | Agent 初始化失败（vocab.json 缺失）                           | 先 `python main.py ingest`                    |
| `429` 请求过于频繁                          | 单客户端超过 30 次/60s                                      | 前端等待窗口恢复；部署检查 §11.1 单进程约束                    |
| LLM 返回 404 / 模型未找到                    | 模型名与 provider 实际加载不符                                 | 本地 provider 的错误提示含检查清单；对照配置模型名               |
| 无法连接本地 LLM（vLLM/Ollama）               | 本地服务未启动/端口错误                                         | 检查服务进程与 VLLM_BASE_URL/OLLAMA_BASE_URL        |
| 会话保存失败提示                              | PostgreSQL 未连接                                       | 检查 POSTGRES_* 与数据库服务；表自动创建                   |
| 图片上传 413                              | base64 超 4M 字符                                       | 前端压缩兜底；确认走的是前端上传而非绕过直传                       |
| 联网搜索不可用                               | TAVILY_API_KEY 未配置                                   | 配置 key；或改用本地工具                               |
| Exa 工具长期不出现                           | Exa MCP 后台启动失败（npx 下载慢/网络）                           | 查看日志「Exa MCP 启动失败」；首次请求后等待后台启动完成，后续请求自动挂载    |
| MCP 进程反复拉起                            | EXA_API_KEY 无效致启动即崩溃                                 | 检查 key；客户端有 30s 重启限频兜底                       |
| 前端流式失效（整段一次显示）                        | 生产环境 SSE 走了缓冲代理                                      | 设置 NEXT_PUBLIC_API_BASE 直连；反代关闭 buffering    |
| `Connection refused (WinError 10061)` | 桌面代理软件关闭后环境代理残留                                      | 本项目已 trust_env=False 规避；确认代码未回退为默认 httpx 客户端 |
| 后台日志出现「LLM 返回函数调用格式, 重试」              | 模型输出工具格式文本                                           | 自动约束重试机制生效，观察是否自愈；频繁出现考虑换模型                  |
| eval 输出乱码                             | Windows GBK 控制台                                      | eval 脚本已 reconfigure UTF-8；仍乱码则用管道重定向文件查看    |
| Excel 脚本 PermissionError              | 目标文件被 Excel 打开                                       | 关闭文件后重试（脚本有明确提示）                             |
| 图谱/数据库工具返回「未连接」但服务正常                  | 配置指向错误地址                                             | 对照 §2.3 检查 NEO4J_*/POSTGRES_*                |

## 13. 开发约定

### 13.1 代码风格

- 注释与日志使用中文，风格为**解释「为什么」而非复述「做什么」**（参考存量代码的段落式注释）
- 常量集中在 `src/agent/constants.py` 顶部并附语义说明；magic number 一律提为命名常量
- 单例命名小写下划线（`rag_pipeline`），类大驼峰（`RAGPipeline`）
- 函数/方法 docstring 说明契约（返回结构、降级行为），generator 注明产出的事件元组

### 13.2 健壮性约定

- 工具/外部依赖必须容错：失败返回结构化错误文本而非抛出（Agent 永不因死后端崩溃）
- 用户可见错误不泄露内部细节（地址/原始异常只进日志）
- 共享可变状态必须加锁（模型懒加载、LLM 客户端缓存、Tavily 缓存、限流器、健康检查缓存）
- 新增外部调用必须考虑超时（LLM 60s / 本地模型 300s / Qdrant 30s / Neo4j 30s / MCP 60s / 工具总 30s）

### 13.3 向后兼容约束（勿破坏）

- SSE `done` 帧字段结构与 `tool_name` 单字符串语义（前端徽标 + eval 指标依赖）
- `from src.agent import ...` / `from src.rag import ...` 公共重导出路径（测试与 eval 依赖）
- 前端落库 `PersistedMessage` 字段形状（`lib/api.ts` 运行时校验会丢弃脏记录）
- `.env` 键名与默认值（README/本文档引用）

### 13.4 文档同步义务

以下改动必须同步文档：

| 改动            | 同步位置                                    |
| ------------- | --------------------------------------- |
| Agent 工具/流程变化 | CLAUDE.md Agent 段、组件工作机制.md 相应章节、本文档 §6 |
| 新端点/字段/错误码    | 本文档 §5、README API 表                     |
| 新配置项          | 本文档 §2.3、CLAUDE.md config 段             |
| 包结构/文件移动      | CLAUDE.md 结构、本文档 §1、组件工作机制.md 路径引用      |
| 技能内容变化        | 对应 SKILL.md 自身                          |
