## 3. 后端框架层

### 3.1 FastAPI + Uvicorn

- **FastAPI 0.139.2**：全部 11 个端点定义于 `api/server.py`；Pydantic 2.13.4 负责请求/响应模型与枚举校验（如 feedback 的 `rating: Literal["up","down"]`）
- **Uvicorn 0.51.0**（`[standard]` 附加项含 websockets/httptools）：生产 ASGI 服务器；`main.py api` 开发模式带 `reload=True`
- **端点模型约定**：全部端点用同步 `def`——FastAPI 自动将同步端点放入线程池执行，慢请求（LLM 生成数十秒）不阻塞事件循环，限流中间件与健康检查始终可用
- **流式**：`StreamingResponse`（`text/event-stream`），响应头 `Cache-Control: no-cache` + `X-Accel-Buffering: no`（防反向代理缓冲）

### 3.2 HTTP 传输

- **httpx 0.28.1**：OpenAI SDK 与 zai-sdk 的底层传输；项目自建 `src/http_client.py` 统一出站策略——`trust_env=False` 不继承系统代理，显式配置 `HTTP_PROXY`/`HTTPS_PROXY` 才走代理
- **requests**（Tavily 客户端用）：同策略封装（`build_requests_session`）

## 4. LLM 层

### 4.1 接入 SDK

| SDK | 版本 | 服务 |
|---|---|---|
| **openai** | 2.48.0 | DeepSeek（OpenAI 兼容协议）+ vLLM / Ollama（OpenAI 兼容端点） |
| **zai-sdk** | 0.2.3 | 智谱 GLM 文本与视觉 |

统一接口 `src/clients/base_client.py`：`chat` / `chat_stream` / `chat_stream_thinking`（思考与正文分离流式）/ `chat_raw`（Agent 读取 tool_calls 用）；工厂 `llm_factory.get_llm_client(provider)` 路由。

### 4.2 模型清单

| Provider | 模型 | 用途 | 关键参数 |
|---|---|---|---|
| DeepSeek | `deepseek-v4-flash`（默认） | 文本主模型（Function Calling） | temperature 0.3 |
| DeepSeek | `DEEPSEEK_THINKING_MODEL`（可选，如 `deepseek-v4-pro`） | 深度思考推理模型 | max_tokens 8192；**省略 tool_choice**（该参数返回 400） |
| 智谱 | `glm-4.7-flashx`（默认） | 文本备选 provider | 同 DeepSeek 接口语义 |
| 智谱 | `ZHIPU_THINKING_MODEL`（可选） | 深度思考备选 | 同上 |
| vLLM | `VLLM_MODEL`（默认 `deepseek-r1-0528-qwen3-8b`） | 本地推理（OpenAI 兼容） | 超时 300s（本地 8B 推理慢） |
| Ollama | `OLLAMA_MODEL`（默认 `deepseek-r1:8b`） | 本地推理 | **跳过 Function Calling**，直接走 RAG 降级路径 |
| 智谱 Vision | `glm-4.6v-flashx` | 图片内容解析（`/api/vision`） | base64 data URL 输入 |

- 前端右上角可逐请求切换 provider（deepseek / zhipu / vllm / ollama），偏好存 localStorage
- 推理模型的 `reasoning_content` 处理：流式时思考与正文分离（thinking/token 两类事件）；正文为空时思考内容兜底为回答

## 5. 嵌入与重排模型（Hugging Face）

| 模型 | 角色 | 细节 |
|---|---|---|
| `BAAI/bge-small-zh-v1.5` | Dense 查询/文档编码 | 512 维；查询带指令前缀「为这个句子生成表示以用于检索相关文章：」；L2 归一化；GPU OOM 自动降级 CPU |
| `BAAI/bge-reranker-base` | CrossEncoder 精排 | 对（query, answer）对打分；召回 30 条后取 top-k |
| jieba BM25 | Sparse 编码 | 精确模式分词（过滤单字）；BM25 权重 → `{indices, values}` 稀疏向量 |

- 载体：**sentence-transformers 5.6.1** + **transformers 5.14.1** + **torch 2.13.0**（CUDA 可用时走 GPU）
- 模型懒加载 + 双重检查锁（并发首用只加载一份）；首次运行从 HF 下载（国内 `HF_ENDPOINT=https://hf-mirror.com`）

## 6. 数据存储

### 6.1 Qdrant（向量库）

- 服务端 **1.18**（Cloud 或自建），客户端 `qdrant-client 1.18.0`
- **Named Vectors**：每点同时存 `dense`（512 维，COSINE）+ `sparse`（BM25）两路向量
- 混合检索经 `query_points` 的 `Prefetch`（双路各召回 30）+ `RrfQuery`（RRF k 按问题类型 30/60/90）原生融合
- 版本注意：`client.search()` 在 qdrant-client ≥1.9 已移除，全部走 `query_points`
- 客户端参数：`trust_env=False`（不继承系统代理）、30s 超时、断连重试 2 次

### 6.2 Neo4j（图数据库）

- 驱动 **neo4j 6.2.0**；服务端 **5.3+**（需支持 `begin_transaction(timeout=...)` 服务端超时）或 6.x
- 星型 schema：SubjectMatter 中心 + Purchaser/Supplier/Agency/Location + HAS_TRANSACTION
- 连接池：max_connection_pool_size=50，max_connection_lifetime=3600

### 6.3 PostgreSQL（关系数据库）

- 驱动：**SQLAlchemy 2.0.51**（Core 用法，仅 `text()` 参数化查询）+ **psycopg 3.3.4**（binary 包）
- 业务表 `bidding_procurement`（18 字段白名单）；`conversations`（messages JSONB）与 `feedback` 表由客户端连接时自动创建
- 安全：字段/聚合函数白名单、参数化 SQL、LIKE 通配符转义（`ESCAPE '\'`）

## 12. 版本兼容性注记（踩坑记录）

| 约束 | 原因 |
|---|---|
| qdrant-client ≥1.9 | `client.search()` 已移除，必须 `query_points` + `Prefetch`/`RrfQuery` |
| Neo4j 服务端 ≥5.3 | `begin_transaction(timeout=...)` 服务端终止慢查询依赖此版本 |
| 深度思考模型省略 `tool_choice` | DeepSeek 推理模型对该参数返回 400，省略即 auto 语义 |
| `load_dotenv(override=False)` | 容器/CI 注入的环境变量不被本地 `.env` 顶掉 |
| 出站 `trust_env=False` | 桌面代理软件关闭后，默认信任环境代理会把全部出站连接路由到失效端口（WinError 10061） |
| OpenAI SDK v2 | 项目代码面向 SDK v2 API（`chat.completions.create` 与 `reasoning_content` 属性访问），升级 SDK 大版本需回归客户端测试 |
| pandas 3.x | batch 管道与导入脚本已适配 3.x 清洗行为（NaN 先 dropna 再转字符串） |
